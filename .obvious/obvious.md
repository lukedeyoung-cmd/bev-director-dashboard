# obvious.md — bev-director-dashboard

## Repository

- **Repo:** `lukedeyoung-cmd/bev-director-dashboard` (private)
- **Purpose:** Standalone Land & Sea Dept beverage-program analytics dashboard.
  Hard rule from Luke: **zero code or data from CocktailCost / Bar Cost** — never
  import, reference, or reuse anything from the cocktailcost repo, its data, or its
  credentials. This project stays fully independent (repo, database, hosting).
- **Set up:** 2026-10-31. Empty repository at start; foundation pushed to `main` directly
  (nothing to protect at the time). Use feature branches + PRs from now on.

## Stack

- Python 3.12+, Flask 3 (application factory in `app/__init__.py`), Gunicorn (`wsgi:app`)
- PostgreSQL + SQLAlchemy 2 models in `app/models/`, Alembic migrations in `migrations/`
- Flask-Login session auth; Flask-WTF CSRF; env-driven config in `app/config.py`
- Server-rendered Jinja2 with the Obvious design system (vendored under
  `app/static/css/styles.css` + `app/static/js/theme.js`); no JS build step
- CI: GitHub Actions (`.github/workflows/ci.yml`) — ruff, Postgres migration cycle, pytest

## Local dev

```bash
python3 -m venv .venv && .venv/bin/pip install -e ".[dev]"
export DATABASE_URL="postgresql+psycopg://bev:bev@localhost:5432/bev"
export SECRET_KEY="$(python3 -c 'import secrets; print(secrets.token_urlsafe(32))')"
.venv/bin/alembic upgrade head
.venv/bin/flask --app wsgi:app create-admin --email you@example.com --name "Name" [--password ...]
.venv/bin/flask --app wsgi:app run --debug
```

- A local PostgreSQL 17 with role/db `bev` / `bev` (password `bev-dev-password`)
  exists in the sandbox for verification.
- `SECRET_KEY` is required — `create_app` raises without it.
- For local plain-HTTP, set `SESSION_COOKIE_SECURE=false` (`.flaskenv` default).

## Conventions

- **Models:** SQLAlchemy 2.0 typed style (`Mapped[...]` / `mapped_column`), UUID
  primary keys (`sa.Uuid`), `TimestampMixin` on shared tables. One domain area per
  module in `app/models/` (`catalog`, `sales`, `purchasing`, `inventory`, `recipe`,
  `mapping`, `user`); `app/models/__init__.py` re-exports all of them — keep that list
  current so Alembic autogenerate sees every table.
- **Migrations:** Never edit an applied revision. After model changes:
  `alembic revision --autogenerate -m "..."`, review the file, then commit. Autogenerated
  files in `migrations/versions/` are excluded from ruff; everything else is linted.
- **Routes:** Blueprints in `app/routes/` (`web` pages, `api` JSON). Auth-gate pages
  with `@login_required`; the `web` blueprint has `login_required` as a default.
- **Templates:** Extend `base.html`; use the design-system classes (semantic tokens,
  `card`, `btn btn-primary`, `input`, `badge`); include the theme-toggle button.
  Every page must handle empty state (see `dashboard.html`'s venue list).
- **Config:** Read environment variables in `app/config.py` only. No secrets in code,
  templates, or the repo. `.env.example` documents the contract.
- **Lint before commit:** `.venv/bin/ruff check .` (line length 100, rules E/F/W/I/B/UP).
- **Tests:** `.venv/bin/pytest -q`. Fixtures live in `tests/conftest.py`; tests run on
  Postgres in CI and sqlite locally via `DATABASE_URL`.
- **Commits:** Conventional prefixes (`feat:`, `fix:`, `chore:`, ...).

## Verification

- `ruff check .` and `pytest -q` must pass before pushing.
- Migration discipline: CI runs `upgrade head` → `downgrade base` → `upgrade head`
  against Postgres; run the same locally before committing a new migration.
- Gunicorn boot check: `gunicorn -b 127.0.0.1:8123 wsgi:app` then
  `curl 127.0.0.1:8123/api/healthz` (expect `{"database":"ok","status":"ok"}`).
